# Mobile push reminders: tasks due tomorrow

The existing Express scheduler now sends Expo remote push to opted-in, active mobile devices for the assignee's incomplete tasks due tomorrow. It keeps existing access/membership checks and the APP_TIMEZONE/REMINDER_CRON schedule (defaults: Asia/Kolkata, 08:00 daily). Email, inbox and web-browser preferences remain separate. Due today, overdue, completed, unassigned, inactive or inaccessible tasks do not get this push type.

## Configure and run

1. Run `npm ci --prefix mobile`. Apply the additive migration to the existing configured database: `node server/scripts/migratePush.js` (or the normal `npm run db:migrate`). No data is dropped.
2. Link mobile to your Expo/EAS project using `npx eas-cli@latest build:configure` from mobile. Keep the provided profiles and project ID. Use a reachable API URL; HTTPS is required for preview/production.
3. In Firebase, register Android app **com.projectmaster.mobile**, download google-services.json and store it outside source control. Set `GOOGLE_SERVICES_JSON` to its local path for native local builds, or create an EAS **file** environment variable with that name pointing to its uploaded contents for your build environment. app.config.ts forwards that path to android.googleServicesFile. This is not an EXPO_PUBLIC variable.
4. Upload the Firebase FCM v1 service-account key through `npx eas-cli@latest credentials` (Android > Google Service Account > Push Notifications FCM V1). Keep service-account private keys out of the repository/app bundle. iOS additionally needs EAS/APNs credentials; iOS delivery is not verified here.
5. In server/.env set `PUSH_ENABLED=true` and `SCHEDULER_ENABLED=true`. Keep APP_TIMEZONE/REMINDER_CRON appropriate to your users. If Expo enhanced push security is enabled, set its **server-only** EXPO_ACCESS_TOKEN. Restart the backend after changing configuration. Missing push tables fail startup when push is enabled.
6. Build and install a native development build (`npx eas-cli@latest build --platform android --profile development`) or preview APK (`--profile preview`). Adding the native plugin requires rebuilding; a Metro reload alone cannot add it. For development, run `npm --prefix mobile run start:dev-client`. Expo Go does not support Android remote push.
7. Sign in, open More > Settings > Mobile push notifications > **Enable push reminders**, and allow the OS notification permission. The preference is account-wide. **Register this device** enables another signed-in device when the preference is already enabled. Disable turns off this reminder type for all devices and unregisters the current device.

Official guidance: [Expo push setup](https://docs.expo.dev/push-notifications/push-notifications-setup/), [FCM v1 configuration](https://docs.expo.dev/push-notifications/fcm-credentials/), [send tickets and receipts](https://docs.expo.dev/push-notifications/sending-notifications/), [Expo Go limitation](https://docs.expo.dev/push-notifications/faq/).

## Behavior and safety

- Only explicit Enable requests permission. Subsequent login/foreground refresh renews an already granted device token without prompting; native token-change events refresh registration.
- Registration belongs to the authenticated account. On an account switch the same Expo token is rebound. Online logout removes the device before requests finish; local JWT removal remains immediate. Offline logout cannot guarantee server deregistration: stale registrations expire after 30 days without renewal, and payload text contains no task names/descriptions. Revoked OS permission removes the current registration when the app next refreshes.
- Tapping a reminder opens Task Details only when its recipient matches the signed-in account and the task ID is valid. Existing server scope checks still apply; inaccessible/deleted tasks show the normal error state.
- Each recipient/task/local-day/token gets one claim, protected by the existing unique delivery key across overlapping workers and same-token re-registration. Task changes are read on the scheduled run; pushes already handed to the provider cannot be recalled. No new tasks are created.
- Expo receives generic lock-screen title/body and task/user IDs for navigation. It receives no JWT/password/project/task descriptions. Device tokens are not returned by preferences or logged. Only authenticated owner deletion is allowed; registration validation and rate limiting are enforced.
- ACCEPTED means Expo accepted a ticket; the existing scheduler checks receipts every 15 minutes after a 15-minute wait and records SENT/FAILED. Even a successful receipt does not guarantee OS display. DeviceNotRegistered removes that device. Provider failures are contained; raw provider error text is never stored. Missing receipts expire after 24 hours.
- Delivery is best effort. Failed/crashed daily claims are not automatically resent, preventing duplicate lock-screen alerts; review FAILED/PROCESSING logs. Push payload expires at the provider after one hour. Large installations should add queued/throttled delivery and retention management; this implementation sends one device per HTTPS call sequentially. Server uptime/outbound HTTPS, configured native credentials and an OS-granted permission are required.

## Automated verification

`npm --prefix server test` includes real guarded MySQL integration coverage for authenticated/strict registration, owner deletion/account rebinding, opt-in, incomplete/tomorrow/access checks, stale-device expiry, overlapping worker deduplication, failures, receipt transitions and invalid-token cleanup. Expo HTTP is mocked, so automated tests never send a real push. `npm --prefix mobile test` covers Go/missing-project/permission conditions, channel/token registration, SecureStore lifecycle and recipient-safe tap targets. TypeScript, Expo Doctor and Android production export check build compatibility.

For a real-device acceptance test, configure the above credentials, assign an accessible incomplete task due tomorrow, enable push, background the native app and wait for REMINDER_CRON. In a development database only, `npm --prefix server run test:reminders` runs the existing daily job immediately. Verify one alert, tap navigation and no duplicate on rerun; complete another task or disable the preference and verify suppression. This script may send real configured email/push, so use demo accounts/dev credentials. Test offline sign-out, account switching, revoked OS permission and invalid-device receipts as well. Actual device delivery requires the deployment credentials and has not been claimed by mock tests.
